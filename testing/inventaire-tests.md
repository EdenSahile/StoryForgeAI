# Inventaire des tests — StoryPilot AI

État réel de la couverture de test, fonctionnalité par fonctionnalité, tel que le code se présente aujourd'hui (pas un plan pour du code à venir).

## Légende

- 🟢 **testable en unitaire** — logique pure, déjà extractible ou extractible dans `src/logic/`, ou déjà couvert par un test de handler `api/*.js` appelé directement, sans rendu.
- 🟠 **mixte** — une part unitaire + une part qui a besoin d'un vrai rendu (React Testing Library / jsdom) ou d'un vrai navigateur.
- 🔴 **nécessite un vrai navigateur** — parcours utilisateur, interaction visuelle, résultat observable seulement à l'écran (Playwright).

## Priorités

1. **`libraryStorage.js` — fonctions pures de l'historique.** Aucun test direct alors que ce module est la source de vérité utilisée par 4 écrans (`Dashboard`, `Results`, `Library`, `Settings`). Une régression silencieuse ici (ex. tri cassé, troncature de titre) se propage partout sans qu'aucun test actuel ne le détecte. Fonctions pures, aucun rendu requis — le test le plus rapide à écrire de la liste.

2. **`ragService.js` — miroir direct de `claudeService.js`.** Même patron déjà éprouvé (mock `fetch`, pas de rendu), et ce service porte l'autre moitié de chaque génération (récupération du contexte RAG). Le compléter ferme la boucle sur le chemin de génération complet.
